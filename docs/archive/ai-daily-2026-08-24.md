## 1. 今日值得看

### 1. Claude Code 2.1.239（confirmed）

**一句话判断：这是一次大规模 Bug 修复 + 稳定性修复更新，涉及 50+ 个修复项，涵盖核心会话恢复、MCP、Remote Control、浏览器集成、安全等多个维度。**

v2.1.239 是近期最"厚"的一个版本。虽然没有新功能亮点，但它解决了一大批影响日常使用体验的底层问题。

#### 1.1 成本估算更准确：US-only-inference 加价 1.1× 入账

`/cost`、状态栏、`--max-budget-usd` 现在会包含数据驻留工作区的 1.1× 美国仅推理加价。这对企业用户来说很重要——以前成本估算可能低估实际花费，尤其是 Bedrock/Vertex/Foundry 等非直连 API 的场景。

#### 1.2 Bedrock 流式传输修复：之前悄悄双倍计费

这是一个严重的计费 bug：当代理服务器剥离了响应的 Content-Type 头时，Claude Code 会把每个 turn 非流式重新跑一遍，等于悄悄双倍计费。修复后，Bedrock + 代理场景的 API 调用恢复正常。**如果你用 Bedrock 并且有代理，强烈建议升级。**

#### 1.3 会话恢复（/resume）全面加固

这一版修了一大批 `/resume` 和 `-c` 的问题：
1) 重命名会话后超过 64KB 对话内容，自定义标题会消失——修了。
2) `/resume` 会从不同目录捞出路径仅差 `_`、`-`、`.` 的会话——修了。
3) `/resume` 在 all-projects 模式下会提示 `cd` 到已删除的 worktree 目录——改为直接在当前目录恢复。

这对经常开多个会话、切目录的用户影响很大。以前 resume 偶尔"接歪"的体验会好很多。

#### 1.4 Agent 会话通讯更可靠

`ListAgents` 和 `SendMessage` 现在能看到活跃的 teammate（之前只能看到 subagent），Windows 上也支持跨会话通讯了。这让多 session 协作的体验更完整。

#### 1.5 /goal 智能退避

`/goal` 的重复 check-in 现在会退避：30min → 1h → 2h，不再每 30 分钟问一次。这对长时间跑任务的场景更友好，减少打扰。

**我的判断：** 值得升级。虽然没新功能，但 Bedrock 双倍计费修复和 /resume 全面加固对日常使用影响很大。

### 3. Codex CLI 0.149.0（confirmed）

**一句话判断：Codex CLI 进入"Agent Dashboard + TUI 交互"时代，管理后台 agent 的体验大幅改善。**

发布于 2026-08-20，功能密度很高。

#### 3.1 Agents Dashboard：可视化管理后台任务

新增交互式 dashboard，可以搜索、启动、打开、重命名和停止后台 agent 任务，支持可配置快捷键。这是 Codex CLI 在 agent 管理上的一大步——以前只能靠命令行或日志追踪后台任务，现在有 TUI 界面对等管理了。

#### 3.2 /cd /pwd /cwd：TUI 内切换工作目录

新增 TUI 内的 `/cd`、`/pwd`、`/cwd` 命令。以前在 TUI 里想切目录得退出再 `cd`，现在可以直接在会话里操作。对多项目切换场景很实用。

#### 3.3 codex queue：向现有会话发消息

新增 `codex queue` 命令，可以向已有的本地或远程会话发送消息。这让跨会话通信和任务协调更灵活，不用再开新会话或手动干预。

#### 3.4 codex doctor 增强

现在能诊断 endpoint 保护、网络/代理故障、desktop app 状态和更新连通性。出问题时先跑 `codex doctor`，比以前能覆盖更多场景。

#### 3.5 SDK 用户的 reasoning effort 选择

SDK 用户可以传入精确的 CLI config override，并选择 max 或 ultra reasoning effort。对用 Codex SDK 做自动化的开发者来说，这意味着可以在代码层面控制推理深度，而不是靠 TUI 设置。

**我的判断：** 值得升级。Agents Dashboard 和 /cd 系列命令是日常使用体验的实质性改善。

来源：[GitHub Release](https://github.com/openai/codex/releases/tag/rust-v0.149.0) / [官方 Changelog](https://developers.openai.com/codex/changelog)

### 6. Cursor：Cloud Agents + Origin Code Hosting（date_uncertain，~Aug 19）

**一句话判断：Cursor 在全面押注"Cloud Agent 生态"——从代码托管、PR 管理到多 VM 子代理，agent 的自主性在快速提升。**

#### 6.1 Subscriptions：Agent 订阅事件源

Cursor Agent 现在可以订阅事件源（PR、Slack thread），并在事件发生时自动醒来工作。Cloud agent 会自动订阅自己创建的 PR 并推动到完成——修 CI、回复 bot 评论。这是 agent 从"被动等指令"向"主动响应事件"转变的关键一步。

#### 6.2 Subagents on their own machines

子代理现在可以在独立的虚拟机上运行，每个都有隔离的项目副本和干净的 context。这让 "swarm of subagents" 模式成为可能——让多个子代理各自在独立环境中测试或修复 bug，互不干扰。

#### 6.3 /goal：长期目标驱动

`/goal` 给 agent 一个长期目标，会持续工作直到完成。配合 Custom Mode（固定 skill 到 chat）和 /loop（定期检查），agent 的自主性进一步增强。

#### 6.4 Origin Code Hosting

Cursor 开始提供代码托管服务——repos、PRs、code browsing、GitHub sync。所有付费计划可用。这意味着 Cursor 从 IDE 进化为"代码平台"。

#### 6.5 Builds：Cloud Agent 启动速度 3x

环境预构建（Builds）让 agent 启动时间缩短 3 倍。坏 commit 或依赖更新破坏环境时，agent 会继续使用上次成功的 build。

#### 6.6 Google Workspace 插件 + iPad 支持

新增 Gmail、Google Drive、Calendar 插件，Cursor agent 可以直接读写 Google Workspace。iPad 版也上线了，支持 split-screen 审查 PR。

**我的判断：** 方向值得关注。Subscriptions 和 Subagents on VMs 是 agent 自主性的重大升级，但具体体验需要实际测试。Origin Code Hosting 是战略级产品，可能改变代码管理格局。

来源：[Cursor Changelog](https://cursor.com/changelog)
